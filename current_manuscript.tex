\abstract{Sepsis is a life-threatening condition that requires early detection to promptly administer adequate therapy (e.g., antibiotics). While various machine learning models have been proposed to detect sepsis using tabular lab features, recent works increasingly integrate the temporal dynamics of a patient’s journey. This integration is achieved by using graphs to represent irregularly sampled (i.e., unevenly spaced over time), sparse electronic health records and applying graph learning (e.g., GNNs) to predict sepsis. However, there is currently no universal, end-to-end workflow capable of rapidly developing, training, and validating these models across diverse feature sets while remaining highly efficient and explainable. To address this gap, we propose GraphFlow, a highly reproducible, Docker-based workflow encompassing data preprocessing, temporal graph construction, and graph learning. Built upon the MIMIC-IV and SBC datasets, GraphFlow leverages the GraphAware framework with mini-batching to enable memory-efficient training on any hardware. We evaluated the Area Under the Receiver Operating Characteristic Curve (AUROC), training efficiency, and hyperparameter tuning \& inference times across various feature sets. Our results show that GraphFlow achieves remarkable peak classification performance with complete blood counts (CBC) and basic metabolic panels (BMP) (complete blood count: 0.930, complete blood count \& BMP: 0.951), competing or even outperforming state-of-the-art GNNs (complete blood count: 0.936, complete blood count \& BMP: 0.923) and common machine learning baselines (complete blood count: 0.836, complete blood count \& BMP: 0.915). Furthermore, to computationally stress-test the workflow against severe real-world data sparsity, we introduced the highly specific hemolysis–icterus–lipemia index (HIL) \cite{Tian2022}. Under this extreme sample size reduction, GraphFlow demonstrated superior robustness (complete blood count, BMP & HIL: 0.944) compared to GNNs (complete blood count, BMP & HIL: 0.893). Additionally, GraphFlow adheres to open science FAIR principles to maximize the transparency, interoperability, and practical reusability of its underlying models and workflows. We demonstrate the interpretability of GraphFlow models using SHAP values, highlighting their capability to deliver transparent predictions to improve clinical trust. Finally, while we exemplify GraphFlow on the use case of sepsis prediction, it can be used for the prediction of other diseases. }

\keywords{Sepsis, Graphs, Graph learning, Graph workflow}

\section{Introduction}\label{sec1}

\subsection{Graph learning improves sepsis predictions}
Sepsis is among the major causes of death worldwide (i.e., 11 million sepsis-related deaths worldwide in 2017) \cite{Rudd2020-lk}. An early detection of sepsis within the first hours is of utmost importance since rapid treatment (e.g., with antibiotics) is essential to prevent life-threatening consequences such as septic shock and multiple organ failure \cite{Evans2021}. Various previous studies have already developed machine learning models for diagnosing sepsis \cite{9005564,chenzhangtang2021,steinbach2024applying,walke2025sbc}. While some studies used a complete bandwidth of clinical tests and biomarkers, achieving remarkable performance \cite{9005564,chenzhangtang2021}, other studies could already show that a few easily available clinical parameters (e.g., complete blood count information) are enough to achieve good diagnostic performance \cite{steinbach2024applying}. Most of these previous approaches consider electronic health records (EHRs) as static tabular information which misses the connections (e.g., time-based patient journey). To include information from missing connections, we previously proposed to use graphs to represent these irregularly sampled and sparse EHRs \cite{walke2023edges} and train Graph Neural Networks (GNNs) on these graphs to improve the classification performance for sepsis. Additionally, we proposed models that could exploit time series information in a patient journey while making predictions interpretable (i.e., to highlight how specific blood parameters influence the sepsis risk) \cite{walke2025sbc}. We abstracted this model training into a framework, GraphAware, to make it compatible across any graph and showed its competitive performance against state-of-the-art GNNs \cite{walke2026graphaware}.

\subsection{Current gap in training prediction models}
However, neither of the previous approaches proposed an end-to-end graph-based workflow for the rapid development of new machine learning models trained on various feature sets. Those workflows would not only facilitate validation against new external datasets, but also allow for rapidly retraining new machine learning models as soon as new data becomes available. Finally, such a workflow could accelerate the development of new machine learning models with diverse feature sets tailored for the demands of clinicians. 

\subsection{Criteria for a universal graph learning workflow}
Such a workflow would have to fulfill a couple of key criteria to prove useful. First, it has to be adaptable to new feature sets. Second, to align with the growing demand for Open Science and FAIR (Findable, Accessible, Interoperable, Reusable) principles \cite{Wilkinson2016}, the workflow must guarantee high reproducibility. It should be deployable on any device, independent of the user's operating system or hardware architecture, effectively overcoming the reproducibility hurdles that currently hamper medical AI. Third, the workflow has to be efficient and should allow training new models even on devices with low working memory to reduce the barriers to use. This efficiency becomes increasingly important in the AI age as GPUs, memory, and hardware in general become increasingly expensive. Furthermore, the framework must guarantee high generalizability on unseen data. Specifically, external generalizability is crucial to ensure the successful application of trained machine learning models across different institutions. Finally, it should make the decisions of the machine learning models transparent, not only for clinicians to increase trust in the models but also for machine learning engineers to question their models' usefulness. 

\subsection{Contributions}
In this study we propose GraphFlow, an end-to-end graph-based workflow for training new machine learning models for sepsis prediction. Specifically, our contributions are as follows:
\begin{itemize}
    \item \textbf{End-to-end pipeline:}We built an end-to-end graph-based workflow utilizing the MIMIC-IV \cite{johnson2023mimic} and SBC \cite{steinbach2024applying} datasets to load patient data, preprocess measurements, construct temporal graph structures, and efficiently query database information for training our machine learning model. To evaluate the external generalizability of our proposed framework, we perform cross-dataset evaluation: training the models on one dataset (e.g., SBC) and testing them on the other (e.g., MIMIC-IV), and vice versa.
    \item \textbf{Memory-efficient training \& explainability:} The pipeline utilizes the GraphAware framework \cite{walke2026graphaware} with mini-batching to train models with minimal memory requirements while fully enabling prediction explainability to make trained models transparent.
    \item \textbf{High reproducibility \& FAIR adherence}: The complete pipeline is modularized in Docker containers and utilizes publicly accessible datasets, guaranteeing Findability and Accessibility. By decoupling the workflow from specific operating systems or hardware architectures, we ensure Interoperability and Reusability, effectively overcoming the reproducibility hurdles that currently hamper medical AI \cite{Wilkinson2016}.
    \item \textbf{Comprehensive baselines:} The workflow integrates common machine learning baselines (Logistic Regression \cite{wright1995logistic}, XGBoost \cite{Chen2016} and Random Forest \cite{Breiman2001}) alongside with state-of-the-art GNNs for comprehensive model comparison. 
    \item \textbf{Extensibility:} Models with various feature sets can be trained easily by editing a configuration file, and new datasets can be integrated by defining a new preprocessing module.
\end{itemize}

\section{Background}
\subsection{Graphs \& irregular time-series information}
A directed property graph $G = (N, E)$ consists of a set of nodes $N$ connected by a set of edges $E$. The set of nodes $N$ represents the entities in the graph, consisting of a unique identifier $i \in I$ and properties $p_n \in P_N$, which can be expressed formally as $N \subseteq \{(i, p_n) \mid i \in I, p_n \in P_N\}$. The set of edges $E$ represents the directional connections between these entities, where each edge has a starting node $u \in N$, and a target node $v \in N$. Additionally, an edge can also contain additional properties $p_e \in P_E$, and therefore an edge can be formally defined as $E \subseteq \{(u, v, p_e) \mid u, v \in N, p_e \in P_E\}$ \cite{angles2018property}.
One example is a patient-specific time series graph \cite{walke2023edges}, where nodes represent measured clinical samples (e.g., complete blood count data) and directed edges connect each sample to all subsequent samples from the same patient (Fig. \ref{fig:background}\,A).


\subsection{Graph Neural Networks (GNNs)}
GNNs are deep learning methods to analyze graph-structured data. They are based on the message-passing framework to aggregate information from a node's neighborhood to iteratively update each node's representation. Specifically, the nodes' representations are first transformed  (e.g., by an MLP) into a message, then aggregated by a permutation-invariant aggregation function (e.g., mean), and finally updated as new nodes' representations (Fig. \ref{fig:background}\,B) \cite{Velickovic.22.02.2022}. This transformation, aggregation and update process is repeated iteratively for $k$ layers so that it can integrate information that is $k$-hops away. The final representations can then be used for the prediction (e.g., predicting sepsis). Formally, a single layer can be defined as:
$$
\bm{h}_u = \phi \left( \bm{h}_{u-1}, \bigoplus_{v \in \mathcal{N}_u} \psi(\bm{h}_{u-1}, \bm{h}_{v-1}) \right) 
$$
where $h_u$ is the current representation of node $u$, $h_u-1$ and $h_{v-1}$ are the representations of node $u$ and $v$ from the previous iteration (at the beginning the nodes' initial features), $\psi : \mathbb{R}^k \times \mathbb{R}^k \to \mathbb{R}^l$ is the message-passing function (e.g., an MLP), $\phi : \mathbb{R}^k \times \mathbb{R}^m \to \mathbb{R}^m$ is the readout function (e.g., an MLP), and $\bigoplus$ is a permutation-invariant aggregation function (e.g., mean) \cite{Velickovic.22.02.2022}.

\subsection{GraphAware \& feature-level interpretability}
While GNNs provide high classification performance, their feature-level interpretability (i.e., investigating the contribution of individual features to the prediction) is limited \cite{walke2026graphaware}. Therefore, we previously proposed the GraphAware framework, which achieved competitive performance compared to state-of-the-art GNNs while being compatible with post-hoc explainability frameworks like SHAP \cite{NIPS2017_7062, walke2026graphaware}.
In this framework, first features are aggregated by a permutation-invariant aggregation function (e.g., difference of current features to the mean of neighboring nodes' features) and for each created feature set (e.g., different neighborhoods) separate classifiers are trained. Finally, the predictions of each classifier are aggregated to a final prediction (Fig. \ref{fig:background}\,C) \cite{walke2026graphaware}.

\section{Methods}
\subsection{Overview}
We propose GraphFlow, an end-to-end graph-based workflow to efficiently analyze irregular time-series data exemplified for predicting sepsis using various lab measurements. This workflow is modularized to ensure quick and easy adoptability to new datasets, reduce complexity, and improve reproducibility of our results. Specifically, we have a module for preprocessing (Section\,\ref{methods:preprocessing}), training baseline machine learning models (Section\,\ref{methods:baseline}), graph construction (Section\,\ref{methods:graph_creation}), database import for the following efficient mini-batch training (Section\,\ref{methods:database_import}), GNN-based mini-batch training (Section\,\ref{methods:gnn}), and GraphAware mini-batch training (Section\,\ref{methods:graphaware}). Additionally, we present an interactive Streamlit dashboard that translates GraphAware's temporal graph aggregations into calibrated sepsis risk predictions, local SHAP explanations, and real-time clinical evaluation metrics (Section \ref{methods:dashboard}). Everything can be deployed via a single Docker Compose script, which builds all Docker services from the individual modules (Section\,\ref{methods:deployment}). We exemplify our pipeline on two datasets (Section\,\ref{methods:datasets}), and evaluate the classification performance (Section\,\ref{methods:evaluation}). Finally, we integrate a Model Context Protocol (MCP) server  \cite{modelcontextprotocol} that provides standardized tools for autonomous Large Language Model (LLM) agents to programmatically orchestrate the pipeline, query experiment metadata, run inference, and generate patient-level explanations (Section\,\ref{methods:mcp}), and list the used hardware for all experiments (Section\,\ref{methods:setup}).

\subsection{Datasets}\label{methods:datasets}
As datasets for the evaluation, we use the Sepsis Blood Count dataset from Steinbach et al. \cite{steinbach2024applying} and the publicly available MIMIC-IV dataset \cite{johnson2023mimic}. 
The Sepsis Blood Count dataset is a dataset with complete blood count information from patients from a non-intensive care unit from two German tertiary care centres collected between 2014 and 2021. Data were compiled from two tertiary care centers—the University Hospital Leipzig (internal dataset) and the University Medicine Greifswald (external validation dataset) and contains a total of 1,819,435 CBC measurements across 723,681 patient cases. The Leipzig cohort contains 708,595 cases (1,381,358 CBCs), comprising 1,960 sepsis cases (2,016 sepsis CBCs) and 706,635 control cases (1,379,342 control CBCs). The Greifswald external validation cohort comprises 157,922 cases (438,077 CBCon over 500,000 patients, including and 157,484 control cases (437,629 control CBCs). Besides complete blood count information (red blood cells, white blood cells, hemoglobin, mean corpuscular volume and platelets) it contains information of the patients' age, sex, and the measurement time \cite{steinbach2024applying}. 
The Mimic-IV \cite{johnson2023mimic} is a publicly available database from the EHRs of the Beth Israel Deaconess Medical Center. It contains information of over 500,000 patients, with information about laboratory tests, diagnoses, treatment orders, and procedures \cite{johnson2023mimic}. In this study, we only focused on sepsis prediction based on different lab parameters.

\subsection{Preprocessing}\label{methods:preprocessing}
Pre-processing was performed according to Steinbach et al. \cite{steinbach2024applying}. Specifically, we removed duplicated blood samples, incomplete samples, cases from the following sepsis episodes, cases with a SIRS but undiagnosed sepsis, and cases admitted to non-medical intensive care units \cite{steinbach2024applying}. We analyzed the MIMIC-IV dataset \cite{johnson2023mimic}, initially restricting features to complete blood count data to cross-evaluate results against the SBC dataset \cite{steinbach2024applying}, before extending the evaluation on MIMIC-IV to the Basic Metabolic Panel (BMP) and hemolysis–icterus–lipemia (HIL) index. 

The BMP (glucose, calcium, sodium, potassium, chloride, bicarbonate, blood urea nitrogen, and creatinine) is commonly obtained upon emergency department admission and provides key measures of renal function, electrolyte balance, and metabolic status that contribute to the assessment of organ dysfunction in patients with suspected sepsis \cite{Evans2021}. Concurrently, the HIL index is a pre-analytical quality metric generated by many modern clinical chemistry analyzers to detect sample interference \cite{Tian2022}. Although HIL indices are routinely generated during chemistry testing, they are not consistently stored in EHR, often being retained only within laboratory information systems or reported when specimen quality is affected \cite{Tian2022}. Incorporating HIL indices therefore evaluates the model's robustness to realistic patterns of missing laboratory data while also allowing exploration of whether these indices provide additional predictive information beyond standard laboratory tests.

Data processing for the SBC \& MIMIC-IV dataset included filtering for adult patients ($\geq$\,18 years), mapping standardized lab labels, and calculating time-to-ICU admission by joining laboratory timestamps with hospital transfer data. Finally, cases were classified into either Sepsis or Control using ICD codes. We used time-based splits for training, hyperparameter tuning (validation), and model evaluation (final testing on a holdout dataset) for each dataset. 

\subsection{Machine learning baselines}\label{methods:baseline}
As machine learning baselines, we used a Logistic Regression \cite{wright1995logistic}, XGBoost Classifier \cite{Chen2016}, and a Random Forest \cite{Breiman2001}. For machine learning training we used the scikit-learn \cite{scikit-learn} and XGBoost library \cite{xgboost}, and Hyperopt for hyperparameter tuning \cite{Bergstra2013}. Finally, models are stored with joblib \cite{joblib} and evaluated (see Section\,\ref{methods:evaluation}).

\subsection{Graph creation}\label{methods:graph_creation}
Graph construction was performed according to Walke et al. \cite{walke2023edges}, utilizing a directed graph structure in which edges point from past measurements to the current measurement. We extended this approach by incorporating the time differences between measurements for individual patients as edge weights. The patient-specific time differences were normalized using a Min-Max Scaler to obtain $\Delta t_{scaled} \in [0, 1]$. The final edge weights were then calculated as $w = 1 - \Delta t_{scaled}$. This ensures that earlier measurements receive lower weights, while measurements closer to the current time step receive higher weights, effectively weighting the feature aggregation to further improve classification performance. Ultimately, this graph structure overcomes the challenge of irregular EHR sampling by fully exploiting available time-series data. By dynamically weighting past connections based on elapsed time, it ensures that the most clinically relevant measurements drive the feature aggregation.

\subsection{Database import}\label{methods:database_import}
Following graph creation, we load the directed graph into an SQLite database to facilitate the retrieval of relevant subgraphs as mini-batches. We selected SQLite specifically because it has demonstrated the lowest query times for mini-batch training of GNNs \cite{walke2026evaluation}. During data import, the dataset is exported to CSV format, and new nodes and edges are iteratively added based on each row. All nodes are stored in a single table containing their measurement ID, patient ID, ground-truth label, and measurement time. For efficient data retrieval, node features are converted to NumPy arrays and stored as binary large objects (BLOBs). Edges are maintained in an edge list comprising the source node identifier, target node identifier, and an edge weight that represents the normalized time difference between individual lab measurements. To accelerate edge creation and optimize subsequent subgraph retrieval, we index the source and target node identifiers \cite{walke2026evaluation}. Finally, to minimize I/O bottlenecks during BLOB retrieval, the SQLite database is hosted on a local NVMe SSD, with all database interactions handled via the official Python SQLite driver (version 3.40.1).

\subsection{GNN training}\label{methods:gnn}
To establish a robust baseline with high representational capacity, we trained a GNN. Specifically, we employed Graph Attention Networks v2 (GATv2) \cite{brody2022how}, as its ability to handle edge weights allows for the direct incorporation of time-series differences between lab measurements (see Section \ref{methods:graph_creation}). GATv2 was selected for its dynamic attention mechanism, which overcomes the static attention bottleneck of the standard GAT \cite{gat} and enhances the model's representational expressiveness \cite{brody2022how}. For feature engineering, we applied min-max scaling to all node features (i.e., sample measurements) and integrated sine-cosine positional encodings to preserve the temporal ordering of measurements during permutation-invariant aggregation in the GNN.

Model training leveraged mini-batching directly from an SQLite database, implemented via PyTorch \cite{PyTorch} and PyTorch Geometric \cite{Fey_Lenssen_2019,Fey_2025}. We optimized hyperparameters (i.e., learning rate, weight decay, number of layers, attention heads, hidden dimensionality, and dropout rate) using Hyperopt \cite{Bergstra2013}. Each model was trained for a maximum of 100 epochs. To mitigate overfitting, we applied early stopping with a patience of ten epochs based on validation performance, ultimately restoring the model weights from the best-performing epoch. Finally, the GNN is evaluated on unseen test data (see Section\,\ref{methods:evaluation}).

\subsection{GraphAware training}\label{methods:graphaware}
The core of our workflow is the GraphAware framework \cite{walke2026graphaware}. However, instead of training separate classifiers for the time-based neighborhood and original features, we concatenate these feature sets and pass them into a single machine learning classifier. Additionally, we extended GraphAware to handle edge weights, allowing us to incorporate time differences directly into the feature aggregation. This incorporation is achieved by scaling the source node features by their corresponding temporal edge weight prior to the permutation-invariant aggregation (e.g., mean aggregation). The incorporation of these time differences successfully improved classification performance on a separate validation dataset. To efficiently evaluate classification performance (see Section \ref{methods:evaluation}) and runtimes (training, hyperparameter tuning, and inference) across our two datasets (see Section \ref{methods:datasets}), we required an algorithm capable of mini-batch training. We selected XGBoost \cite{Chen2016}, as it demonstrated the most promising results in previous work \cite{walke2025sbc} while fully supporting mini-batch updates. Hyperparameters were optimized using Hyperopt \cite{Bergstra2013}. Finally, similar to the GNN, GraphAware is evaluated on unseen test data (see Section\,\ref{methods:evaluation}). For model interpretability, we generated SHAP summary plots \cite{NIPS2017_7062}, aggregating the SHAP values of the original and time-based features into a unified representation for clarity.

\subsection{Dashboard}\label{methods:dashboard}
To translate this complex end-to-end workflow into actionable, transparent clinical insights, an interactive inference and decision-support dashboard was developed using Streamlit \cite{streamlit} and Plotly \cite{plotly-source_2026}. During inference, the system dynamically ingests laboratory trajectories to construct patient-specific graphs and predict time-point sepsis risk using GraphAware. To handle severe class imbalance, raw predicted probabilities are rescaled, mapping the validation-calibrated decision threshold to a 50\% risk score. While precision-based metrics like AUPRC are avoided for global evaluation due to prevalence-driven disparities \cite{NEURIPS2024_4df3510a}, bedside thresholding optimizes the $F_2$ score ($5 \cdot \frac{\text{Precision} \cdot \text{Recall}}{4 \cdot \text{Precision} + \text{Recall}}$), weighting recall twice as heavily as precision to prioritize early detection over false positives. For interpretability, SHAP TreeExplainer \cite{NIPS2017_7062} attributes predictions to baseline physiology and temporal dynamics. Finally, when ground-truth labels are available, the dashboard evaluates standard clinical metrics (e.g., AUROC, $F_2$, sensitivity, specificity, PPV), ROC curves, and confusion matrices.

\subsection{Evaluation Metrics}\label{methods:evaluation}
To evaluate model performance, we primarily rely on the Area Under the Receiver Operating Characteristic curve (AUROC). While the Area Under the Precision-Recall Curve (AUPRC) is frequently assumed to be superior for imbalanced medical datasets like our sepsis cohorts, recent theoretical and empirical work by McDermott et al. \cite{NEURIPS2024_4df3510a} refutes this notion. Their findings demonstrate that AUPRC can unduly favor model improvements in subpopulations with more frequent positive labels, heightening algorithmic disparities. Therefore, AUROC serves as a more robust and equitable metric for our framework. All evaluation metrics and execution times (training, hyperparameter tuning, and inference) are logged using MLflow \cite{Zaharia_Accelerating_the_Machine_2018}. Finally, container memory consumption (RAM) is continuously polled from the Docker daemon at two-second intervals to compute and log the peak RAM usage for each active module. 

\subsection{Deployment and Reproducibility}\label{methods:deployment}
To ensure computational reproducibility and isolate software dependencies, each system module was independently containerized. Specifically, we developed dedicated Dockerfiles for every component, facilitating the seamless construction and execution of isolated Docker environments across different hardware setups. Additionally, further features of the MIMIC-IV dataset can easily be integrated by appending the item IDs to a CSV list, and the utilization of other datasets merely requires adapting the preprocessing module without changing any other downstream module. This modularity allows for easier applicability to datasets from institutions unable to share raw data, and enables extensibility to other clinical targets by optimizing against different labels.

By open-sourcing the GraphFlow codebase on GitHub and Docker containers on DockerHub, and grounding our evaluation in standard datasets (MIMIC-IV \cite{johnson2023mimic} and SBC \cite{steinbach2024applying}), this deployment strategy adheres to the FAIR principles \cite{Wilkinson2016}. To guarantee Findability and Accessibility, all code, container images, and experimental metadata—tracked via MLflow (i.e., hyperparameters, inference times, and AUROC scores) are publicly available. Furthermore, the pipeline persistently stores intermediate artifacts at each discrete step, including preprocessed data, constructed graph representations, and SQLite databases. This containerized architecture ensures Interoperability and Reusability, allowing external researchers in the future to integrate specific pipeline modules, validate the workflow without dependency conflicts, and effectively overcome the reproducibility hurdles that currently plague medical AI.

\subsection{Model Context Protocol Integration}\label{methods:mcp}
To enable programmatic orchestration (i.e., the automated, code-driven execution and management of complex workflow steps within GraphFlow) and seamless integration with autonomous Large LLM agents, we implemented a custom MCP \cite{modelcontextprotocol} server using FastMCP \cite{fastmcp2024}. The server exposes standardized Remote Procedure Call (RPC) tools (i.e., protocols that allow AI agents to execute functions on the system remotely, e.g., requesting a model evaluation and receiving structured results) without manual terminal interaction. Specifically, the server provides endpoints to:
\begin{enumerate}
    \item \textbf{Orchestrate Pipeline Execution:} Inspect available stages and programmatically trigger individual modules or the complete workflow (e.g., running baseline model training or graph construction) with laboratory panel filtering and automated process management.
    \item \textbf{Query Experiment Metadata:} Retrieve tracked evaluation metrics (such as AUROC, sensitivity, and specificity) alongside hyperparameters and optimal Geometric Mean, Receiver Operating Characteristic (ROC) classification thresholds directly from the MLflow database.
    \item \textbf{Perform Programmatic Inference and Interpretation:} Execute GraphAware feature aggregation and XGBoost risk scoring (automatically defaulting to evaluation datasets when specific file paths are omitted) and compute $2N$ aggregated local SHAPley Additive exPlanations (SHAP) \cite{NIPS2017_7062} feature contributions (i.e., $N$ baseline laboratory values plus $N$ temporal neighborhood adjustments) for individual patient trajectories.
    \item \textbf{Manage Dashboard Services:} Programmatically inspect network port availability and launch or restart the interactive background Streamlit User Interface (UI) inference dashboard.
\end{enumerate}
By encapsulating execution, evaluation, interpretability, and UI control within structured RPC endpoints, this MCP integration provides an agent-ready framework for reproducible clinical AI deployment.

These summary plots can improve the understanding of the underlying ML model and help identify which features are important and how a feature value influences the prediction. The larger a positive SHAP value is, the greater the feature's contribution to the prediction 'Sepsis', while more negative SHAP values contribute toward 'Control'. For example, a high white blood cell (WBC) count is rather associated with the prediction "Sepsis" and a lower value with "Control". Additionally, the magnitude of SHAP values from smallest negative to the largest positive value represents the importance of an individual feature. For example, for our prediction white blood cells, age and sodium concentration were the three most important features, while sex and hemoglobin were the least important ones.
The discrete vertical banding observed in the SHAP summary plot reflects the shallow tree architecture ($\text{max\_depth} = 1$ decision stumps) selected during hyperparameter tuning. Rather than outputting a continuous risk score curve, the ensemble partitions continuous laboratory values into discrete risk thresholds (e.g., distinct step jumps in Sepsis risk when WBC exceeds $12.0 \times 10^9/\text{L}$).

\section{Discussion and limitations}\label{discussion}
In this section, we first discuss the improved classification performance and external generalizability achieved by our time-aware graph learning approach (Section \ref{disc:cbc}). Next, we examine the framework's robustness across diverse feature sets and its resilience to severe clinical data sparsity (Section \ref{disc:other_features}). Finally, we highlight how visualizing feature contributions enhances model interpretability (Section \ref{disc:interpret}) and demonstrate the practical utility of our interactive dashboard and programmatic orchestration tools for real-world clinical deployment (Section \ref{disc:case_mcp}).

\subsection{GraphFlow achieves the highest generalizability when trained on SBC
data}\label{disc:cbc}
With GraphFlow, researchers can now efficiently develop and evaluate new models for the prediction of sepsis using diverse feature sets. Our results demonstrate that the implemented graph learning baselines (GNN \& GraphAware) consistently outperform traditional machine learning baselines across the evaluated feature sets, highlighting the value of incorporating time-based information.

Furthermore, our evaluation on the SBC data (SBC Test AUROC: 0.938) shows an improvement over previous prospective studies evaluating this dataset (which reported SBC Test AUROC: 0.900) \cite{walke2023edges}. We attribute this classification performance gain to the additional integration of time differences within the time series of each patient journey. Notably, this integration significantly improved the external generalizability of sepsis prediction on complete blood count data, increasing the external AUROC from 0.834 \cite{walke2023edges} to 0.903 in this study.

We also found that training on the SBC dataset yielded substantially better generalizability (MIMIC-IV Test AUROC: 0.919) compared to training on the MIMIC-IV dataset (SBC Test AUROC: 0.894). This enhanced robustness can likely be explained by the larger number of training samples in SBC (1,015,074 samples) compared to MIMIC-IV (880,100 samples). Finally, while GraphAware achieved a slightly lower classification performance on the internal dataset compared to the GNN (AUROC 0.919 vs. 0.938), it demonstrated superior external generalizability when trained on SBC data (MIMIC-IV Test AUROC 0.919 vs. 0.889).

This external generalizability is particularly important when deploying machine learning models in distinct laboratory institutes. The divergence in external generalizability between the GNN and GraphAware architectures can likely be attributed to their underlying learning paradigms. While deep learning models like GNNs are highly expressive and allow them to achieve peak performance on internal datasets (SBC Test AUROC: 0.938) by learning complex, latent structural representations, their high expressiveness makes them more susceptible to learning institute-specific artifacts (i.e., overfits them on the institute they were trained on), which hinders cross-institute transferability. In contrast, GraphAware's XGBoost provides inherent regularization through boosted tree ensembles, which rely on robust statistical boundaries, resulting in superior transferability when deployed on external datasets (MIMIC-IV Test AUROC: 0.919).

\subsection{GraphFlow achieved the highest performance across most feature sets in MIMIC-IV}\label{disc:other_features}
Additionally, we demonstrated that GraphFlow is robust across diverse feature sets and that the integration of complementary clinical features (e.g., BMP) can further enhance classification performance, yielding an AUROC of up to 0.951. However, when highly specific feature sets are integrated (e.g., HIL), the classification performance drops for the graph learning-based approaches (AUROC up to 0.944). This deterioration is primarily driven by the lower availability of complete patient samples containing all target features (complete blood count: 880,100 samples vs. complete blood count\,\&BMP\,\&HIL: 115,393 samples). Notably, this reduced sample availability affects the GNN (where AUROC drops to 0.893) much more severely than our GraphAware model (which retains an AUROC of 0.944). This divergence aligns with architectural expectations: deep learning models like GNNs exhibit higher sample complexity and require larger volumes of training data to generalize effectively, whereas the standard machine learning estimators integrated within our GraphAware framework generalize robustly with fewer observations (see Section \ref{disc:cbc}). 

This severe sample reduction accurately reflects routine clinical workflows, where specialized panels like the HIL index are ordered only under specific diagnostic suspicions rather than as universal baseline screens. While restricting the dataset to these specific cases introduces clinical selection bias, it provides a strict methodological stress test of the GraphFlow architecture. This clinically driven data sparsity without imputations exposes the vulnerability of highly complex GNNs, while the ability of our GraphAware ensemble to maintain high predictive stability demonstrates its resilience and practical utility in real-world, resource-constrained environments.

Conversely, while performance dropped for our graph-based approaches and Logistic Regression, the AUROC scores for Random Forest and XGBoost remained relatively stable when adding HIL features to the baseline complete blood count \& BMP configuration (shifting marginally from up to 0.910 to 0.912 in the Random Forest). This resilience indicates that these ensemble models successfully balance the added informational value of the new features against the statistical challenges of a reduced sample size. 

In this study, we explicitly avoided basic imputation techniques (e.g., zero-filling, mean/median substitution, or last-observation-carried-forward) to prevent embedding systemic clinical biases (e.g., the implicit predictive weight of a clinician's decision to order a specific test) and to avoid distorting actual patient phenotypes with generalized statistical averages. Future work will explore the integration of advanced, context-aware imputation methods, such as Multiple Imputation by Chained Equations (MICE) \cite{Azur2011} or time-aware deep learning architectures like BRITS \cite{BRITS}, into the preprocessing module to safely retain incomplete samples and maximize dataset utility. Crucially, because GraphFlow is fully containerized, future researchers are not constrained by our baseline decision to drop incomplete samples. Advanced, time-aware imputation frameworks can be directly embedded into the preprocessing module of GraphFlow, allowing clinicians to retain all samples without requiring downstream modifications to the graph construction or machine learning Docker containers.

While the machine learning baselines underperformed the graph-based architectures in most evaluation scenarios, XGBoost still demonstrated robust baseline capabilities, achieving an AUROC of 0.836 on complete blood count data alone. Furthermore, XGBoost (AUROC: 0.915) outperformed the GNN (AUROC: 0.893) on the most restricted feature set (complete blood count \& BMP \& HIL) while demanding orders of magnitude less computational overhead (e.g., under 3\,s for training on complete blood count data). This performance-to-compute trade-off positions ensemble methods like XGBoost as highly viable candidates in resource-constrained clinical settings where training efficiency and inference latency are prioritized over marginal optimization metrics. Although our database-backed mini-batching already enables highly memory-efficient model training on such hardware, future work could further reduce the peak memory footprint of the preprocessing module by implementing batched data loading or executing feature transformations directly within the database.


\subsection{GraphFlow provides model interpretability by visualizing SHAP values}\label{disc:interpret}
Finally, we demonstrated the interpretability of GraphFlow through GraphAware's compatibility with SHAP values \cite{NIPS2017_7062,walke2026graphaware}. By visualizing the aggregated global importance of features, we improve the transparency of how predictions are derived. For clinical applications, this resulting interpretability is crucial as it not only increases the trustworthiness of the trained machine learning models but also allows clinicians to verify that the model's predictive logic aligns with established physiological mechanisms (e.g., the strong association between elevated white blood cell counts and sepsis). Beyond validating the model's predictive logic, this transparency facilitates the discovery of latent patterns within complex datasets. By highlighting strong associations between specific features and clinical outcomes, such interpretability can generate new hypotheses regarding patient pathophysiology, thereby assisting in the identification of novel biomarkers for challenging diagnoses.

\subsection{Clinical Case Utility, Interactive Visualization, and Workflow Orchestration}\label{disc:case_mcp}

The evaluation of the clinical case study in Section~\ref{res:case_study} underscores the necessity of temporal sensitivity, threshold calibration, intuitive visual interpretability, and programmatic interoperability when deploying graph learning models in critical care environments.

In clinical datasets characterized by low disease prevalence, default classification thresholds ($\tau = 0.50$) are often ill-suited for highly imbalanced prediction tasks such as sepsis detection. By calibrating decision thresholds through $F_2$-score optimization on validation splits, GraphFlow explicitly prioritizes sensitivity over precision. Clinically, this design decision minimizes false negatives to safeguard against delayed antibiotic administration during early sepsis \cite{Evans2021}. As demonstrated in our case study, baseline static models failed to issue an alert because single-timestamp feature vectors could not capture the patient's subtle physiological deterioration over time. In contrast, GraphAware's temporal edge weighting successfully aggregated recent longitudinal trajectories (such as progressive shifts in white blood cell counts and electrolyte balances), elevating the predicted risk score beyond the operational threshold ($\tau$). Furthermore, coupling these predictions with local SHAP explanations enables clinicians to distinguish baseline risk factors from acute temporal changes, establishing the transparency required to build clinical trust in medical AI recommendations.

Interactive web dashboards play a crucial role in translating these complex graph-based predictions into bedside clinical utility. By rendering real-time risk trajectories, calibrated decision boundaries, and local SHAP feature contributions, the interactive dashboard provides essential visual auditability for practicing physicians. This human-in-the-loop review mechanism allows clinicians to rapidly contextualize model predictions against longitudinal physiological trends, ensuring that model outputs align with clinical judgment before initiating high-stakes medical interventions.

To complement visual exploration and streamline pipeline operations, we integrated a standardized MCP server into our GraphFlow framework. Rather than assuming immediate integration into fully automated hospital environments, MCP acts as a bridge between containerized Docker services and programmatic research workflows. A primary objective behind modularizing GraphFlow into Docker containers was to enable the rapid development and retraining of models across diverse clinical feature sets. The integration of MCP further accelerates this process by exposing standardized RPC tools directly to LLM agents. Automated agents can programmatically trigger data preprocessing, execute model retraining on new laboratory panels, inspect MLflow experiment metadata, and perform programmatic inference with structured SHAP explanations without requiring manual terminal commands or interface navigation. By combining an interactive visual dashboard with an MCP-compliant interface, GraphFlow delivers a versatile framework that supports both immediate human-in-the-loop clinical verification and streamlined, reproducible AI workflow orchestration.

\section{Conclusion and future directions}\label{sec13}
In this study, we introduced GraphFlow, which establishes a robust and highly adaptable foundation for advancing medical AI in real-world, resource-constrained clinical environments. By effectively modeling irregularly sampled EHRs as graphs, achieving time-series analysis capabilities comparable to state-of-the-art GNNs, and providing highly interpretable machine learning models, GraphFlow successfully unites highly accurate predictions with transparent decision-making. "Additionally, the integrated dashboard and MCP server streamline model retraining, provide intuitive risk visualizations, and enable natural language interaction with patient data and predictions. While the current implementation successfully overcomes major reproducibility and generalizability hurdles in sepsis prediction, its containerized, modular architecture is explicitly built to be easily extended and adapted over time. Moving forward, researchers can readily expand this framework to address new methodological challenges and broader clinical applications across the following key areas:
\begin{itemize}
    \item \textbf{Further diseases}: Finally, other studies can investigate further diseases or conditions (e.g., thrombosis or diabetes). Similar to the introduction of new datasets by developing a new Docker container for pre-processing, other studies can use a different label as the prediction target.
    \item \textbf{Further datasets}: Similar to extending feature sets, it is only necessary to customize the preprocessing Docker module and swap the Docker container in the workflow pipeline. Future researchers can easily integrate further datasets like AmsterdamUMCdb \cite{Thoral2021} and HiRID \cite{faltys2021hirid}, including time-series information of any length.
    \item \textbf{Further feature sets}: In the future, other feature sets (e.g., other lab panels, features extracted from image or textual data) could be integrated into the training to further improve the performance. For extending the feature sets, it is only necessary to customize the pre-processing Docker module (e.g., by reading more features from a CSV input or integrating foundation models to extract textual or image information).    
    
\end{itemize}
